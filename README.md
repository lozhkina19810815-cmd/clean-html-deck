# Как мы собираем аккуратные презентации в Claude Code

Коротко: не один волшебный скилл, а четыре слоя. Базовый скилл верстает, фирменный слой
даёт «нашесть», самопроверка ловит технический брак, арт-директор смотрит глазами зрителя.

```
 бриф ─► 1. БАЗОВЫЙ СКИЛЛ ──► 2. ФИРМЕННЫЙ СЛОЙ ──► рендер PDF ──► 3. САМОПРОВЕРКА ──► 4. АРТ-ДИРЕКТОР ──► человеку
         (как верстать)       (из чего верстать)                  (технический брак)   (вкус и уровень)
                                                                         ▲                    │
                                                                         └──── ВЕРНУТЬ ◄──────┘
```

## 1. Базовый скилл — skills/clean-html-deck/SKILL.md
Как верстать: слайды 1920×1080 в HTML+CSS → PDF через Chrome. Одна сетка, шкала размеров,
приёмы (кикер, карточки, крупная цифра, вывод внизу). Взят за основу открытый набор
claude-code-design (MIT) — https://github.com/bluzir/claude-code-design (`/make-deck`, экспорт в PDF/PPTX).
Почему HTML: агент видит результат сам (читает страницы PDF) и правит до показа — нет слепых итераций,
как с .pptx.

## 2. Фирменный слой — brand/BRAND.md
Из чего верстать: цвета, 2 шрифта, логотип, банк фото, правила бренда и 3–5 слайдов-эталонов.
Базовый скилл ничего не знает о бренде — он берёт переменные цветов и шрифтов отсюда.
Поэтому один раз заполнить, и любая новая презентация сразу «ваша».
Правила бренда копятся из правок заказчика: каждая правка, которая повторилась, становится строкой
в BRAND.md, и агент больше её не допускает. У нас за полгода набралось 12 правил.

**Как это устроено у нас.** Фирменный слой — не один файл, а связка с нашими гайдами,
которые агент обязан открыть до первой строки вёрстки (это прописано в скилле презентаций):
- гайдлайны и логотипы брендов — только вектор из папки «Логотипы и Гайдлайны» на Диске, не растр;
- гайд по вёрстке носителя — текст, переносы, сетка, работа с фото продукта;
- правила для имиджевых презентаций — те самые 12 пунктов из правок;
- банк фото — только из актуальной презентации франшизы, каждая точка сверяется с реестром
  работающих точек (закрытая точка на фото = брак);
- эталоны вкуса и журнал реакций заказчика — «что показали → что сказали дословно → класс ошибки».
  Его же читает арт-директор: так он знает планку не в общем, а нашу.
Для себя заведите то же: гайд бренда → правила из правок → эталоны с реакциями.

## 3. Самопроверка — раздел 5 базового скилла
Агент сам открывает каждую страницу PDF и прогоняет скрипт: ничего не вылезает за слайд,
текст не обрезан в карточке, блоки не налезают, нет висячих предлогов, орфография.
Это ловит технический брак, но не вкус.

## 4. Арт-директор — agents/art-director.md
Отдельный помощник (субагент) с чистого листа: не видел, как собирали, поэтому смотрит
как зритель. Перед оценкой читает фирменный слой (гайды, эталоны, журнал реакций). Получает PNG/PDF слайдов + эталон, по каждому слайду — понятна ли мысль за 3 секунды,
одна ли сетка, уровень не ниже эталона. Вердикт ПРОПУСТИТЬ / ВЕРНУТЬ с конкретными правками
(«слайд 4: заголовок сократить до строки»). ВЕРНУТЬ → агент правит и отдаёт на повторный взгляд.
Человеку показываем только то, что прошло оба фильтра.

## Как поставить
1. Положить `skills/clean-html-deck/` в `.claude/skills/` проекта, `agents/art-director.md` — в `.claude/agents/`,
   `brand/` — в корень проекта и заполнить.
2. В CLAUDE.md проекта одной строкой: «Презентации — скилл clean-html-deck; перед показом —
   арт-директор на рендере».
3. Запрос: «Сделай презентацию на 10 слайдов по этому брифу» + бриф / тезисы.

## Что важнее всего (по нашему опыту)
- Красота начинается со смысла: заголовок-вывод и одна мысль на слайд — до вёрстки.
- Проверять по картинке, не по коду: «скрипт сказал ок» ≠ «выглядит ок».
- Эталон рядом обязателен — без него ни агент, ни арт-директор не знают планку.
